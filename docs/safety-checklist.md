# The Safety Checklist

Print this. Tape it where you work. It compresses chapters 2 and 3 into the
two minutes before you let an agent touch anything.

## Before a new tool or folder ever gets connected

- [ ] **Narrow the scope.** The tool touches exactly the folders the task
      needs — one notes folder, not the whole drive.
- [ ] **Read-only until proven.** If read access answers the question, grant
      only that for now.
- [ ] **Approval prompts ON** for anything new.
- [ ] **Backup copied.** A quick folder copy with today's date. (If
      OS-level backups run daily, say so out loud and feel briefly smug.)
- [ ] **Know the exit.** You can point to how you'd disconnect the tool in
      under a minute.

## Before giving a big job

- [ ] **First phrase is "show me the plan"** or "list what you *would*
      change" — then approve.
- [ ] **Sample before bulk.** "Do the first three, then ask me."
- [ ] **A log of actions.** Ask the agent to list every change it made, so
      a reversal is possible.
- [ ] **Time to watch.** Not while you're cooking dinner. First runs get
      supervision.

## Never, for now (review yearly)

- [ ] Banking, payment details, tax filings
- [ ] Passwords, IDs, insurance portals
- [ ] Anything medical or regulated: no clinical decisions, no protected
      patient data — education and organization only
- [ ] The only copy of anything

## After every session

- [ ] Glance at what changed (one `ls`, one look at the folder).
- [ ] Delete anything odd; investigate if it's repeated.
- [ ] Note in `prompts.txt` which requests worked — your personal script of
      sentences that behave.

## The one-sentence version

> Narrow access, watch the first runs, keep backups, and review what it did.

If a step here ever feels like friction — good. That feeling is you being
the kind of user agents can't accidentally hurt.
